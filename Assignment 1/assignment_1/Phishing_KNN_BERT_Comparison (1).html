Phishing email classification with KNN



This notebook uses the first 1,000 data rows of Phishing_Email.csv.

1. TF-IDF KNN baseline.
2. Bonus 1: BERT CLS versus average token embeddings.
3. Bonus 2: original 768D CLS versus 2D PCA and 2D UMAP.

All experiments share a stratified 80/20 split (seed 42) and 5 neighbors. PCA and UMAP fit on training data only. BERT is frozen, not fine-tuned. Results are computed when you run the cells; no BERT results have been precomputed.

def evaluate_knn(name, train_X, test_X, metric):
    model = KNeighborsClassifier(n_neighbors=K, metric=metric, algorithm="brute")
    model.fit(train_X, y[train_idx])
    predicted = model.predict(test_X)
    scores = {
        "Representation": name,
        "Dimensions": train_X.shape[1],
        "Distance": metric,
        "Accuracy": accuracy_score(y[test_idx], predicted),
        "Phishing F1": f1_score(y[test_idx], predicted, average="binary",
                                pos_label="Phishing Email", zero_division=0),
        "Macro F1": f1_score(y[test_idx], predicted, average="macro", zero_division=0),
        "Weighted F1": f1_score(y[test_idx], predicted, average="weighted", zero_division=0),
    }
    return scores, model

Extract BERT embeddings once


The first run downloads bert-base-uncased and requires internet access. CPU extraction can take several minutes; CUDA is used if available. Emails are truncated to 256 tokens.

CLS is the first token's final hidden state (not the pooler output). Average pooling uses all non-padding tokens, including CLS and SEP:

$$e_{avg}=\frac{\sum_i m_i h_i}{\sum_i m_i}$$

The mask excludes padding. Both representations have 768 dimensions.
In [ ]:
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
print("Device:", device)
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
bert = AutoModel.from_pretrained("bert-base-uncased").to(device)
bert.eval()
cls_batches, average_batches = [], []
BATCH_SIZE = 16
with torch.inference_mode():
    for start in range(0, len(texts), BATCH_SIZE):
        inputs = tokenizer(texts[start:start + BATCH_SIZE], padding=True,
                           truncation=True, max_length=256, return_tensors="pt").to(device)
        hidden = bert(**inputs).last_hidden_state
        mask = inputs["attention_mask"].unsqueeze(-1).to(hidden.dtype)
        cls_batches.append(hidden[:, 0, :].cpu().numpy())
        average_batches.append(((hidden * mask).sum(1) / mask.sum(1).clamp(min=1)).cpu().numpy())
        if start % (BATCH_SIZE * 10) == 0:
            print(f"Processed {min(start + BATCH_SIZE, len(texts))}/{len(texts)}")
X_cls = np.concatenate(cls_batches)
X_average = np.concatenate(average_batches)
assert X_cls.shape == X_average.shape == (len(df), 768)
print("Embedding shape:", X_cls.shape)

Bonus 2: 768D CLS versus 2D PCA and UMAP


Both reducers take original CLS embeddings as input. UMAP is not applied to PCA output. Neither reducer receives class labels.

The main comparison uses cosine distance for original BERT and Euclidean distance for 2D coordinates. Because distance also changes, an additional all-Euclidean control is reported below.

Interpretation and limitations


- Report actual macro F1, phishing F1, and weighted F1 from the tables. A tie is possible; small differences on 200 test rows may not be robust.
- PCA preserves maximum variance rather than class separation; reducing to 2D can discard useful signals.
- UMAP emphasizes local neighborhoods but may distort distances. It can help or hurt KNN.
- Average pooling combines token information; raw pretrained CLS is not fine-tuned for this task.
- The first 1,000 rows may not represent the whole dataset. Exact duplicates across the random split can inflate performance; see the diagnostic above.
- Empty texts and truncation affect results. This is one split, with fixed settings and no test-driven tuning. For stronger conclusions, use duplicate-grouped evaluation and training-only cross-validation.
- BERT artifacts are reproducible in method, but numerical results may vary slightly across hardware and package versions.
